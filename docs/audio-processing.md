# Аудиотракт Hub

Общий код находится в `packages/audio/src`, браузерный адаптер LiveKit —
`apps/web/src/voice/audio`. Electron использует ту же сборку React и тот же процессор.

## Фактическая цепочка

Микрофон → getUserMedia constraints (echoCancellation, autoGainControl,
noiseSuppression) → AudioWorklet 48 kHz → RNNoise при выбранном Enhanced →
VAD/PTT gate и плавный gain 0…1 → MediaStreamDestination → LiveKit LocalAudioTrack.
Процессор подключается **до** публикации трека. Камера не захватывается.
Уровень для VAD измеряется до RNNoise/gain; meter показывает уровень входа,
а индикатор затвора — разрешение передачи. Mute остаётся отдельным запретом публикации.

- Выключено: browser noiseSuppression=false, RNNoise не загружается.
- Стандартное: browser noiseSuppression=true, дополнительного DSP шумоподавления нет.
- Улучшенное: RNNoise, browser noiseSuppression=false. Двойного шумоподавления нет.
- voiceIsolation задаётся только после feature detection: включена в Standard,
  выключена в Off/RNNoise. Одновременно с RNNoise не применяется.
- Echo cancellation и AGC независимы от режима шумоподавления.

WASM и PCM выполняются в AudioWorklet, не в UI thread. Блок RNNoise — 480 samples
(10 мс при 48 kHz); worklet адаптирует блоки Chromium через ограниченный ring buffer.
Это размер DSP-блока, **не измеренная полная задержка звонка**. Нет передачи PCM
в сторонний сервис, локального мониторинга в динамиках и внешней телеметрии.
При ошибке инициализации Enhanced интерфейс сообщает о переходе в Standard,
возвращает соответствующие capture constraints и продолжает запуск микрофона.
Для надёжного возврата browser NS Chromium повторно захватывает микрофон: один
applyConstraints может принять параметр, не изменив фактическую обработку.

## Настройки

Input/output устройства можно менять без выхода из комнаты. Названия появляются
после разрешения микрофона. Output применяется через HTMLMediaElement.setSinkId
ко всем подписанным remote audio, включая screen audio; в браузере без этого API
список скрыт. Исчезнувшее устройство заменяется Default с уведомлением.
Gain 100% = 1.0, 0% = тишина, усиления сверх исходного сигнала нет.
Плавное изменение gain уменьшает щелчки; clipping входа показывается отдельно.

Автоматическая чувствительность оценивает шумовой фон с ограниченным порогом.
Ручная — от −80 до −10 dBFS. VAD: attack 30 мс, гистерезис 6 dB, hangover 250 мс.
Это локальный энергетический VAD, не распознавание речи. На громком постоянном шуме
может потребоваться ручной порог или PTT. PTT обходит VAD, отпускание 0…1000 мс.
В web PTT действует только в активном окне; потеря фокуса закрывает затвор.
В desktop используются явно назначенные global shortcuts, см. windows-desktop.md.

Профиль «Изоляция голоса»: RNNoise, echo cancellation и AGC, автоматический VAD.
«Студия»: без noise suppression и AGC, низкий ручной порог; echo настраивается отдельно.
«Пользовательский»: все параметры. Изменение отдельного параметра выбирает этот профиль.

«Проверить микрофон» создаёт отдельный локальный capture/process track без PeerConnection
и публикации. Во время звонка сначала выключите микрофон. Закрытие настроек, остановка
теста и logout освобождают capture. Прослушивания нет, поэтому случайного feedback нет.

Индивидуальная громкость сохраняется по стабильному LiveKit identity пользователя,
применяется официальным RemoteAudioTrack.setVolume (0…1) при каждом subscribe/reconnect.
Deafen принудительно обнуляет только локальное воспроизведение всех участников;
после снятия восстанавливает индивидуальные значения и не включает/выключает микрофон.

## Хранение и измерения

`hub.audio.v2` в localStorage: устройства, gain, режимы, чувствительность, PTT,
профиль и participantVolumes. Миграция читает прежний `hub.voice.processing`.
Некорректные значения ограничиваются/сбрасываются; секреты сюда не записываются.
Desktop OS-настройки отдельно: schema v1, атомарная запись JSON в userData.

Meter обновляется 10 раз/сек; зелёная/жёлтая/красная зоны и clipping-индикатор.
Worklet считает недостающие выходные samples (underflows). Отношение времени обработки
к 10 мс показывается только при доступном performance.now; иначе «измерение времени
недоступно». Это локальная диагностика, не гарантия realtime на любом компьютере.
CPU/аудиозадержку и качество на настоящей гарнитуре нужно проверить в Windows.
