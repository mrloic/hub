| Этап | Статус | Содержание |
| --- | --- | --- |
| 1. Текстовый сервис | проверено | БД → сессии → сообщества/права/приглашения → чат/UI → тесты |
| 2. Голос | проверено | Self-hosted LiveKit/WebRTC, микрофон, участники, индикатор речи, reconnect; медиатокены после проверки прав |

## Принятые решения
- Один API-процесс, без Redis и очередей. Этап 2 добавляет self-hosted LiveKit.
- PostgreSQL хранит сессии; случайный cookie, в БД только его SHA-256.
- HTTP выполняет все записи; Socket.IO сообщает об изменениях без текста сообщений.
- История — страницы по 50 сообщений; повторная сверка загруженных страниц с БД,
  включая удаление и правки. Курсора событий нет: порядок socket-событий не считается порядком commit.
- Приглашения и изменения сообщества сериализуются блокировкой строки сообщества;
  вступление дополнительно блокирует приглашение. Владение передаётся транзакционно.
- Графитовая тема с мятным акцентом, без фиктивного наполнения.
- Локальный Node.js допускается в игнорируемом .tools, без системной установки.

## Этап 2 — решения
- Channel.type = TEXT/VOICE, прежние записи получают TEXT миграцией без удаления данных.
- Одна VoiceLease на пользователя в PostgreSQL; смена комнаты сериализуется блокировкой User.
- Токены на 60 секунд, microphone + screen_share + screen_share_audio / subscribe; без camera, data и admin.
- Signaling /livekit/rtc проходит через backend: сессия + Origin + JWT + актуальная lease/права.
  Это закрывает повторное использование отозванного self-hosted токена.
- RemoveParticipant и закрытие signaling socket при logout/kick/leave/delete; сверка каждые 2 секунды.
- Локальный ICE/TCP 127.0.0.1:7881 через дополнительный SSH -L; signaling через текущий 8080.
- Административный LiveKit 7880 не опубликован. UDP/TURN/публичная сеть не настраиваются.
- Голосовая панель живёт на уровне аккаунта, независимо от выбранного текстового канала.
