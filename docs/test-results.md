## Что проверяет голосовой сценарий

Интеграция с настоящим SFU: MEMBER получает JWT только для VOICE своего сообщества;
посторонний, TEXT, неизвестный канал, подмена room/userId отклоняются. Проверяются
минимальные grants, подпись, Origin/CSRF, cookie чужой сессии, конкурентные join
(валидна ровно одна lease), старый leave, kick, rename/delete и logout.

Два независимых браузерных context подключаются к LiveKit через loopback TCP-forward,
моделирующий оба SSH -L. Проверяются реальные inbound-rtp bytesReceived и говорящий
участник, микрофон, deafen, сохранение отключённого воспроизведения после повторного
входа, переключение текста без выхода из голоса, смена комнаты, kick/delete/logout,
понятный отказ микрофона. Исходный JWT выдерживается более 60 секунд, затем разрыв
и восстановление проверяют обновление токена самим SFU. Нет mock backend/SFU/SDP;
синтетический только источник звука. Ошибок JavaScript не обнаружено.

Текстовые e2e сохраняют исходные сценарии обмена/правки/удаления, reconnect,
пагинации и отдельную фазу реального restart PostgreSQL/API/Caddy. Test volumes
сохраняются; рабочая БД не использовалась для создания тестовых аккаунтов.

- Устранены гонки очистки отменённого подключения и сверки SFU participants.
- SDK diagnostic logs выключены, Caddy фильтрует request в error logs.
- Проверка разрешения микрофона учитывает denied до вызова захвата; ошибки локализованы.

## Непроверенное и ограничения

Физические микрофоны/наушники, слышимость человеком, конкретный Windows SSH-клиент,
две физические машины, Firefox/Safari/Edge и физический телефон не проверены.
Для двух компьютеров достаточно собственных SSH-туннелей к Ubuntu: публичный
доступ для этого не обязателен. UDP, NAT/STUN/TURN, публичные домены/HTTPS и нагрузка
относятся к следующему сетевому этапу; см. [voice-local.md](voice-local.md).

Один API и SFU. При недоступности служебного API LiveKit мгновенное прекращение
существующего медиапотока не гарантируется; отзыв повторяется, новый signaling
по утраченным правам запрещён. 20 участников — лимит комнаты, не замер ёмкости.
Голос не E2EE. На момент этого исторического прогона камера/экран не реализовывались.
Экран добавлен позже: см. [актуальные проверки](features-checks.md). Vite предупреждает о JS chunk >500 kB;
http-proxy печатает предупреждение Node о deprecated util._extend. Это не ошибки
сборки/сценариев. Публичная готовность не заявляется. Traces с cookies/JWT не публикуются.

## Покрытие

Unit: полная матрица управления/исключения/удаления по ролям; login normalization,
кириллическое имя; запрет лишних role fields; ограничения текста и UUID;
публичный HTTPS/Secure mode и запрет слабого секрета/неправильного local URL.

Integration: CSRF и Origin, чужое сообщество/история/socket subscribe; конкурентное
приглашение с лимитом 1 и повторный вход; отзыв/истечение приглашения; дедупликация
конкурентной отправки, новый UUID при одинаковом тексте; правка/удаление и пустой
текст в повторном ответе; отсутствие событий у постороннего; запрет самоповышения,
правила ADMIN, запрет выхода владельца, атомарная передача; reconnect и исключение
подключённого; пагинация/границы курсора; истечение открытой сессии; rate limit;
удаление канала; logout и недействительность старого cookie; вход с нормализацией,
неверный пароль, ротация сессии, профиль и дубликат логина.

Playwright, без mock backend:
1. Два независимых контекста регистрируются, создают сообщество/канал/приглашение,
   вступают, обмениваются сообщениями. Проверяется реальное состояние WebSocket
   «На связи», правка/удаление у обоих, refresh, новый текст и правка/удаление во
   время offline, безопасный HTML-подобный текст, ручной retry без дубля,
   вложенный маршрут, desktop/mobile, отсутствие непредвиденных JS/console ошибок.
2. Сохранённые cookie и история после настоящего restart PostgreSQL/API/Caddy.
3. 55 сообщений через настоящий API, подгрузка старой страницы: положение видимого
   сообщения сохраняется; новое сообщение не прокручивает читающего вниз.

Двухфазный запуск намеренно пропускает restart-сценарий до перезапуска, а после
перезапуска — уже выполненные сценарии. Совокупно выполнены все три, это не
непроверенные тесты. Test-сервисы остановлены скриптом, volumes сохранены.
Local-сервисы оставлены работающими. В рабочей БД 0 пользователей; все тестовые
аккаунты/сообщения изолированы в hub_test.

## Не проверено / ограничения

- Настоящее подключение из CMD Windows: команду выполняет пользователь; проверена
  схема same-origin через Caddy и привязка loopback, но не его конкретный SSH-клиент.
- Восстановление дампа по инструкции backup, отказ физического диска/VM.
- Нагрузка, число одновременно поддерживаемых пользователей, внешний security audit,
  image vulnerability scan, Firefox/Safari и физические телефоны.
- Публичный домен/HTTPS/сеть, email/recovery и LiveKit — не реализованы на этом этапе.

Известных блокирующих ошибок текстового сценария на проверенной конфигурации нет.
Один API-процесс, периодическая сверка каждые 5 секунд, общий peer-IP лимит за Caddy,
окно истории 1000 сообщений с переходом к более старым окнам, последние 100 приглашений
в списке; черновики ограничены жизнью вкладки. Подробности — architecture/security.
Секреты, cookie и полные сетевые traces не включены в этот отчёт.
