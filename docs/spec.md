# Требования к Hub — текст, голос и демонстрация экрана

## Назначение и границы
Hub — самостоятельный сервис общения с сообществами и текстовыми каналами.
Первый этап должен работать с настоящими пользователями и PostgreSQL, без демонстрационных
данных, внешнего backend, зависимости от Codex/ChatGPT или туннеля разработки.
Интерфейс и документация — русские; имена кода — английские. Production: https://hub.mrloic.ru; локальный режим: HTTP через localhost:8080.
Текст ниже описывает границы этапа 1; голос/LiveKit расширены разделом этапа 2.
Личные диалоги, реакции, ответы, непрочитанное, аватары,
файлы — будущие функции. DNS/HTTPS/TURN/NAT уже настроены владельцем и сохраняются.

## Окружение и ограничения
Windows 11 Pro → Hyper-V Hub-Server → Ubuntu Server 24.04 x86_64, 4 vCPU,
8 ГБ RAM, диск 128 ГБ. Docker и Compose уже установлены.
Не переустанавливать систему, не менять SSH, AppArmor, firewall, sysctl, группы,
sudoers, Docker socket, DNS, роутер, UPnP и прокси. Не публиковать Git и сервис.
Не читать приватные SSH-ключи, авторизацию Codex и чужие проекты. Не удалять
пользовательские файлы и volumes; не применять down -v/prune/reset.
Доступ к инструментам разработки может требовать уже существующий прокси;
его адрес не входит в конфигурацию приложения. Локальные связи идут напрямую.
TLS не отключать, случайные registry/mirrors не использовать. Системные изменения
требуют отдельного согласования. Docker используется через sudo при необходимости.

## Стек и структура
React + TypeScript + Vite + Tailwind CSS; NestJS/Node LTS, Socket.IO;
PostgreSQL + Prisma с версионированными миграциями. npm, точные версии и настоящий
lock-файл. Модульный монолит; apps/web, apps/api, packages/shared, infra, scripts, docs, tests.
Без обязательных Redis, медиасервера, микросервисов и Kubernetes.

## Интерфейс
Тёмный графитовый интерфейс приложения, собственный текстовый знак Hub, мятный
акцент. Слева сообщества, рядом каналы, в центре сообщения, справа скрываемые
участники, снизу профиль. Desktop и телефон; клавиатура, подписи и видимый фокус,
нативные modal dialogs с возвратом фокуса, загрузка/пустые состояния/ошибки.
Удаление сообщества/канала подтверждается. Без фиктивных статусов и неработающих
кнопок будущих функций. Новый аккаунт получает выбор создания или приглашения.

## Аккаунты
Уникальный login: trim + lowercase, ASCII a–z/0–9/_, 3–32 символа.
Отдельное отображаемое имя 1–64 символа, включая кириллицу, редактируется владельцем.
Пароль 12–128 символов, Argon2id; не хранить/логировать открытый пароль.
Регистрация/вход/выход; постоянная авторизация через серверную сессию в PostgreSQL,
HttpOnly SameSite cookie, срок жизни/отзыв/ротация при входе; перезапуск API не
теряет сессии. Нет auth-токенов в localStorage. Публичный режим требует HTTPS и Secure.
Email, подтверждение почты, восстановление доступа обязательны перед публичным запуском.

## Сообщества и права
Создание, список своих сообществ, изменение названия, участники, каналы (первый
«общий»), переименование/удаление каналов, выход, исключение, роли,
атомарная передача владения и удаление сообщества.
OWNER — все настройки, роли, передача и удаление. ADMIN — название, каналы,
приглашения, модерация обычных участников и их сообщений. MEMBER — чтение,
отправка, правка/удаление собственных сообщений, выход.
OWNER назначает CO_OWNER/CO_OWNER/ADMIN; CO_OWNER назначает/снимает ADMIN и управляет MEMBER,
но не OWNER/CO_OWNER. ADMIN не управляет OWNER/CO_OWNER/CO_OWNER/ADMIN.
Только OWNER меняет CO_OWNER, передаёт владение и удаляет сообщество.
OWNER не может выйти без передачи владения. Подмена userId/role/communityId
не даёт доступа. Изменения членства/ролей/каналов обновляют открытые интерфейсы.

## Приглашения
Криптографически случайный токен; ссылка из APP_URL; заданные срок 1–720 часов
и лимит 1–1000 вступлений, список и отзыв для OWNER/CO_OWNER/ADMIN.
Неизвестная/отозванная/просроченная/исчерпанная ссылка отклоняется.
Проверка лимита и членство атомарны при конкуренции. Повторный вход участника
не создаёт членство и не расходует лимит. Маршрут приглашения сохраняется при
регистрации/входе. Список показывает последние 100 приглашений сообщества.

## Чат
История из БД, страницы по 50 (не вся история в памяти), отправка обычного текста
до 4000 символов, серверное время/автор/отметка правки. Запись через HTTP;
Socket.IO сообщает об изменениях. Подтверждение отправки только после commit.
У каждой отправки UUID, уникальная пара authorId/clientId в БД; retry не дублирует,
новый UUID разрешает намеренный повтор текста. Состояния отправки/успеха/ошибки
и повтор. Правка только своего; удаление своего либо по правам модерации;
текст удалённого очищается, отображается заглушка у всех.
При reconnect обновляются аккаунт, доступ, сообщества, каналы и загруженная
история, включая правки/удаления. Гонки загрузки и событий обрабатываются
отбрасыванием устаревших ответов; периодическая сверка покрывает потерю события
между commit и отправкой. Курсора изменений нет. Черновики/неуспешные отправки
остаются в sessionStorage текущей вкладки, без токенов авторизации.
Подгрузка сохраняет видимый якорь; новые сообщения не тянут вниз читающего историю.
Старые диапазоны листаются окнами до 1000 сообщений, доступна кнопка возврата
к последним. Текст не интерпретируется как HTML.

## Безопасность
На каждом HTTP-запросе и socket handshake — проверка действующей сессии;
при subscribe — проверка сообщества и канала. Изменяющих socket handlers нет.
События персональные, без содержимого сообщений. Выход отзывает соединения
сессии, исключение/роли сбрасывают выбор подписки, срок сессии контролируется
таймером и периодической проверкой БД. Строгий Origin, подписанный CSRF token
с двойной передачей, server validation strict schemas, ограничение JSON 16 КБ,
socket payload 8 КБ, rate limits входа/регистрации/приглашений/сообщений.
Нет wildcard credential CORS, доверия к произвольным forwarded headers,
stack trace/секретов в ответах и логах. Не заявлять E2EE.

## Размещение и данные
В локальном текстовом режиме только host bind 127.0.0.1:8080. API и PostgreSQL не публикуют host ports.
Caddy отдаёт production frontend, /api и /socket.io проксирует без SPA fallback;
отсутствующие assets дают 404. Маршруты интерфейса обновляются напрямую.
Внутри контейнеров слушать интерфейсы Docker-сети. Без публичных сертификатов.
Windows CMD: отдельный SSH-туннель `ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8080:127.0.0.1:8080 hub`.
Не запускать второй hub-proxy.
Dockerfiles, healthchecks, persistent volume PostgreSQL, ограниченные логи,
restart policies, graceful shutdown, отдельные миграции и тесты. Сборка не
выполняется на старте API. Секреты генерируются без перезаписи .env; секретов,
дампов, ключей, node_modules нет в Git/build context. Нет известного admin password,
privileged/host network/Docker socket/home mounts. API/Caddy работают не от root.
Сборка и тесты учитывают память/CPU; обычное обновление сохраняет данные.
Backup pg_dump и восстановление только в отдельную тестовую БД.

## Проверка готовности
Lint/typecheck/unit/build, интеграционные тесты с реальной отдельной PostgreSQL,
Playwright с независимыми browser contexts, проверка Compose и фактического запуска.
Основной сценарий: регистрация двоих → сообщество/канал → приглашение → чат в
реальном времени → правка/удаление у обоих → refresh → restart с сохранением истории
и сессии. Дополнительно дубли, конкурентный лимит, роли, посторонний пользователь,
чужие socket-события, исключение подключённого, logout/expiry, reconnect, CSRF/Origin,
HTML-текст, вложенные маршруты и телефон. Результаты фиксировать без секретов;
различать написанные/выполненные тесты. Не заявлять нагрузочную ёмкость и публичную
готовность без отдельных проверок.


## Этап 2: локальные голосовые каналы

- Channel.type: TEXT/VOICE; прежние данные остаются TEXT. OWNER/CO_OWNER/ADMIN создают,
  переименовывают и удаляют оба типа; MEMBER подключается к голосу и выходит.
- Self-hosted LiveKit на той же Ubuntu в Compose, без Cloud/Redis/публичной сети.
- Backend проверяет сессию, сообщество, членство, VOICE channel и выводит room name
  самостоятельно. Token разрешает microphone/screen_share/screen_share_audio и subscribe; без camera/admin/data.
- Secret только API/LiveKit, JWT в памяти браузера. Сохранены CSRF/Origin/session проверки.
- Одна voice lease на аккаунт, включая разные вкладки. Переключение текста сохраняет
  голос. Logout/expiry/kick/leave/delete отзывают доступ и активные подключения SFU.
- Панель: connect/disconnect, mic mute, playback mute, реальные участники, говорящий,
  connecting/reconnecting и ошибки микрофона. Автоматического захвата при входе нет.
- Миграции не сбрасывают существующую БД; volumes не удаляются.
- На host дополнительно только loopback 7881/TCP; signaling через исходный 8080.
  SSH -L 7881 нужен отдельно от HTTP. UDP/NAT/TURN/DNS/HTTPS — будущая проверка.
- Тесты token/access/room tampering/revocation, реальное WebRTC audio с fake microphone,
  плюс весь существующий текстовый набор. Исторический этап 2 не включал экран; текущие дополнения ниже.

## Этап подготовки публичного домашнего размещения

Актуальное дополнение: текст и локальный голос сохраняются. Подготовить отдельный
production (`APP_ENV=production`, APP_NAME=Hub, APP_URL=https://hub.mrloic.ru,
VOICE_ENABLED=true), не запускать публикацию автоматически. Local/test остаются
изолированными. Домены hub/rtc/turn.mrloic.ru, адрес только `<PUBLIC_IPV4>` в примерах.
DNS Beget, NAT на роутере и firewall выполняет владелец вручную. Без платных ресурсов.

Caddy выдаёт frontend, API и Socket.IO; RTC signaling защищён шлюзом Hub на отдельном
домене. Автоматические доверенные сертификаты после DNS/NAT. TURN/TLS разделяет
443/TCP по SNI, LiveKit использует 7882/UDP mux и фиксированный внешний адрес за NAT.
TURN аутентифицирован и ограничен peer SFU. Нет публичных API/БД/SSH/debug-портов.
Рабочая БД в существующем external volume, backup/restore отдельно, никаких down -v.

Проверить Secure/HttpOnly/SameSite, CSRF/Origins, доверенный IP для rate limiting,
минимальные voice grants и отзыв. Не передавать секреты клиенту/в логи. Выполнить
доступные регрессии и проверки конфигураций, различать изолированные проверки и
пока невыполненные внешние HTTPS/WebRTC/перезагрузки Hyper-V. DNS/NAT/полный публичный
запуск — [USER ACTION] по public-deployment.md. Продуктовые функции не добавляются.

## Текущее дополнение: UI, роли и экран

Production уже работает публично по сообщению владельца. Этот этап сохраняет
DNS/NAT/топологию/секреты, обновляет только приложение и добавляет enum CO_OWNER
после backup. Перечень прав — architecture.md. Миграция не изменяет членства.

Пять изменений: общий backdrop/Escape/cancel/focus для диалогов; CO_OWNER;
три включённые по умолчанию WebRTC настройки микрофона с локальным сохранением;
стабильные карточки с border/glow вместо текста речи; штатная демонстрация экрана
LiveKit с выбором удалённой трансляции, contain/fullscreen/закрытием просмотра.
Системный звук необязателен и зависит от браузера/источника. Микрофон не включается
автоматически. Экран доступен только в подключённом голосовом канале и останавливается
при выходе/отзыве доступа. Остановка в браузере обновляет Hub. Максимальный профиль
1080p/15fps; камера отсутствует. Krisp Cloud не становится зависимостью self-hosted Hub.

Проверки включают privilege escalation всех ролей, реальные PostgreSQL/LiveKit,
два независимых браузерных контекста, экран/несколько публикаций/stop/ended/cleanup,
размеры speaking/muted карточек, mic constraints и регрессию текста/перезапуска.
Физический экран, звук и системный selector проверяются отдельно человеком.

## Windows и расширенный локальный голос

Windows x64 Electron использует единственную сборку apps/web и существующие публичные
Hub/LiveKit, без backend на ПК. Контекст renderer изолирован, Node выключен, sandbox
и проверка TLS/CSP сохранены; узкий IPC только для desktop UX, настроек и capture.
NSIS installer собирается на Windows, unsigned допустим без обхода SmartScreen.
Автозапуск/уведомления и назначения global shortcuts требуют явного выбора.

Общий voice control: input/output, gain 0…100%, локальный тест/meter, профили,
VAD с hysteresis/attack/hangover или PTT с release delay. RNNoise WASM локален,
без Krisp/платных audio services/CDN и двойного NS; ошибки Enhanced возвращают Standard.
Громкость собеседников 0…100% сохраняется локально по identity; deafen и mute независимы.
Screen share использует прежний LiveKit transport, Electron desktopCapturer и
опциональный Windows loopback. Камера, auto-update и мобильные клиенты вне этапа.
Существующие production данные, secrets, DNS/NAT/ports сохраняются.
