# Безопасность и границы доверия

Локальный режим закрыт на loopback Ubuntu; production уже опубликован владельцем. SSH и доверенные пользователи домашнего
сервера — внешняя граница; настройка SSH не входит в Hub.
Данные передаются браузеру через SSH-туннель, внутри Docker — HTTP/PostgreSQL.
Hub **не использует сквозное шифрование (E2EE)**. Администратор БД может читать сообщения.

## Реализованные меры

- Argon2id 64 MiB / 3 итерации / parallelism=1, пароли 12–128 символов.
- Случайный cookie 256 бит, SHA-256 в БД; expiresAt 7 дней; ротация/отзыв,
  HttpOnly и SameSite Strict, Secure строго для APP_ENV=production.
- HMAC CSRF cookie+header и точный Origin, включая register/login; credentials
  только same-origin. Socket Origin проверяется до handshake, затем сессия из БД.
- Строгие Zod-схемы, исключение лишних полей role/userId; проверки прав в транзакции.
- RateLimit в PostgreSQL переживает restart: регистрация 20/час на сетевой адрес,
  login 60/мин на адрес и 10/5мин на логин, приглашения create 20/мин и join 30/мин
  на аккаунт, сообщения 60/мин (send/edit), subscribe 120/мин на аккаунт.
  Фиксированные окна допускают удвоение на границе; это ограничение алгоритма.
- `trust proxy=false`. В production Caddy заменяет X-Hub-Proxy/X-Hub-Client-IP;
  IP для лимитов принимается только с проверенным отдельным PROXY_SECRET.
  Произвольные X-Forwarded-* не влияют на IP/HTTPS; local использует peer API.
- JSON ≤16 KiB, Socket payload ≤8 KiB, текст ≤4000 символов, история 50/запрос.
- Клиентский текст выводится React как text, CSP запрещает внешние и inline scripts.
- Нет request/body logging. Не выводим cookie, пароль, приглашение, stack trace.
  Внешние ошибки безопасные; непредвиденные ошибки логируют лишь класс.
- Secrets/дампы/ключи исключены из Git и Docker context; случайные локальные секреты
  генерируются с exclusive create и правами 0600. Default admin отсутствует.
- API и Caddy не root; нет host network/privileged/socket mounts; БД без host port.

## Что учитывать

Приглашение — bearer-секрет: знающий ссылку может вступить до срока/лимита/отзыва.
Ссылки доступны только управляющим сообществом. Отозванное приглашение не исключает
уже вступивших. Повтор участника идемпотентен, даже если лимит уже исчерпан.
Роль автора удалённых аккаунтов не возникает (удаления аккаунта пока нет); бывший
участник при модерации рассматривается как MEMBER. Удаление сообщения очищает
текст в актуальной записи; старые backup/WAL могут содержать прежний текст.
Черновики остаются в sessionStorage, на общем компьютере следует закрыть вкладку.
UI не предлагает production mode в локальной конфигурации.

## Перед публичным запуском

Подтверждение email и безопасное восстановление аккаунта; политики хранения,
удаления и обработки обращений; проверка регистрации/защиты от перебора и спама;
проверка HTTPS/Caddy и Secure cookie на настоящем домене;
DNS/порты/firewall отдельно; backup за пределами сервера с проверкой восстановления;
мониторинг и alerting; аудит зависимостей/контейнеров; security review и нагрузочные
измерения на 4 vCPU/8 ГБ. Один процесс API нельзя просто горизонтально масштабировать:
для событий/отзыва сессий понадобятся согласованные механизмы между экземплярами.
Голос использует self-hosted LiveKit/WebRTC. JWT живёт 60 секунд и разрешает
публикацию микрофона/экрана/звука экрана и подписку в одной серверной комнате. LiveKit 7880
доступен только в Docker; signaling проходит через шлюз Hub с проверкой cookie,
Origin, JWT и актуальной VoiceLease. При отзыве закрываются signaling-соединения
и вызывается RemoveParticipant; фоновая сверка повторяет неудавшийся отзыв.
Изолированный от API, но ещё передающий звук SFU не гарантирует немедленное
исключение: см. [локальные ограничения](voice-local.md). Клиент не получает API secret.
LiveKit 7881 опубликован только на loopback для SSH-перенаправления ICE/TCP.
Голос не E2EE: SFU имеет доступ к медиаданным. Диагностические логи SDK выключены,
Caddy удаляет request из error logs, чтобы не сохранять JWT в query string.
Перед публичным запуском отдельно проверяются TURN, HTTPS/WSS, отзыв доступа при
сетевых отказах и сохранение защиты signaling при использовании отдельного домена.


## Подготовленная production-конфигурация

Local по-прежнему закрыт; публичный запуск выполнен владельцем. Exact Origin для API,
Socket.IO и RTC: https://hub.mrloic.ru. Cookie остаётся host-only, rtc использует
JWT + проверку DB-сессии/lease (см. architecture.md). Caddy security headers:
CSP с единственным дополнительным rtc origin, HSTS без includeSubDomains/preload,
DENY framing, nosniff, no-referrer, камера запрещена; display-capture разрешён только self. Нельзя включать debug
и request access logging: signaling query содержит token.

Production volume БД external; новые volumes только сертификатные. Приложения
не root, без privileged/host network. TURN peer ACL и allocations ограничены;
80/443 TCP и 7882 UDP — вся публикация. Системный firewall не применялся.
Подготовленная конфигурация не заменяет публичный security/load review,
мониторинг диска/ошибок и регулярную проверку восстановления backup.

До приглашения неограниченного круга пользователей остаются обязательными
email/recovery из исходного ТЗ либо отдельно согласованная политика закрытого пилота,
защита от массовой регистрации/DoS и порядок обработки персональных данных.
Конфигурация не утверждает, что эти продуктовые/эксплуатационные задачи решены.

## CO_OWNER и захват экрана

Совладелец не управляет OWNER/другим CO_OWNER, не назначает CO_OWNER, не удаляет
сообщество и не передаёт владение. Эти запреты проверяет API, включая подмену полей.
Экран не вводит новый token endpoint: короткий JWT выдаётся после прежних проверок
session/member/channel/lease. Grants ограничены microphone, screen_share,
screen_share_audio; камера/admin/data запрещены. Захват запускается явным действием
пользователя через браузерный selector; Permissions-Policy display-capture=(self).
CSP/origin/CSRF и сетевые маршруты сохранены. SFU видит медиа: это не E2EE.
При отзыве lease прекращаются все её медиапубликации, включая экран.
Настройки обработки локальны и не содержат секретов. Обработка WebRTC не обещает
полного удаления фоновых звуков. Внешние Krisp модели/лицензии не подключены.

## Desktop и локальный DSP

Electron: contextIsolation=true, sandbox=true, nodeIntegration=false, webSecurity=true.
Preload не экспортирует fs/exec/произвольный IPC. Main проверяет sender/mainFrame/origin,
запрещает чужую навигацию, webview и камеру; внешние HTTP(S)-ссылки открывает браузер ОС.
Сессии остаются HttpOnly-cookie; renderer settings не содержат паролей и server secrets.
RNNoise обрабатывает PCM локально; в LiveKit публикуется итоговый track.
WASM разрешён CSP точечно (wasm-unsafe-eval), без сторонних origins.
PTT опрашивает только назначенные клавиши; глобальная запись клавиатуры отсутствует.
Автозапуск/уведомления выключены до согласия. Installer unsigned; SmartScreen не обходится.
Перед распространением требуется Windows проверка cookie forwarding, capture permissions,
PTT в фоне/игре и установка/удаление. Ubuntu unit/e2e не заменяют эту проверку.
